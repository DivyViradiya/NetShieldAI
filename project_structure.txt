1. The Grand Architecture
We will move away from "one file per scanner" and move toward a Plugin Architecture. Your Flask app will act as the "General," and the tools are the "Soldiers."

The Pipeline Flow:

Input: User creates a "Project" (URL + Source Code + Cloud Creds).

Orchestration: The System spawns independent threads for each tool.

Normalization: A specialized "Parser" converts every tool's weird JSON output into a single standard format.

Compliance Engine: Maps the Normalized Findings to PCI/ISO/GDPR.

Reporting: Generates the Master Audit PDF.

2. System Prerequisites (The Installation List)
Before writing code, your server needs these tools installed. You cannot run subprocess if the binary isn't there.

The "apt-get" / Install List:

Semgrep: pip install semgrep

Checkov: pip install checkov

Gitleaks: Download binary (Go-based) or brew install gitleaks (Linux/Mac).

Nmap: sudo apt-get install nmap

Prowler: pip install prowler (Requires AWS CLI configured).

ZAP: Already installed.

3. Database Design (The Backbone)
We need a robust schema to handle this. We shouldn't store 6 different types of results. We store Raw Reports and Normalized Findings.

New Models (extensions.py):

AuditProject: Represents the target (e.g., "E-commerce V1").

id, name, target_url, source_code_path, cloud_provider.

AuditRun: A specific execution time.

id, project_id, timestamp, status (Running/Completed).

ScanResult: The raw output file from a specific tool.

id, run_id, tool_name (e.g., 'Semgrep'), raw_json_path.

Finding: The normalized vulnerability.

id, run_id, tool_source, severity (Critical/High...), cwe_id, description, file_location.

ComplianceReport: The final score.

id, run_id, standard (PCI/GDPR), score, compliance_data_json.

5. The "Normalizer" (Crucial Step)
Every tool speaks a different language. We need a translator.

Semgrep outputs: {"results": [{"check_id": "...", "path": "..."}]}

Gitleaks outputs: [{"Description": "...", "File": "..."}]

Nmap outputs: XML (usually).

We will create Services/normalizer.py:

Python

def normalize_finding(tool_name, raw_data):
    # Returns a standard object:
    return {
        "tool": tool_name,
        "name": raw_data['title'],
        "severity": map_severity(raw_data['severity']), # Map all to HIGH/MED/LOW
        "cwe": raw_data.get('cwe', 'Unknown'),
        "description": raw_data['message']
    }

Note: This requires handling AWS Keys securely. For MVP, we might ask the user to upload a Prowler JSON report manually instead of running it, to avoid liability of holding their root keys.

Here is the strategy to stop that from happening. We will use a Three-Layer Defense.

Layer 1: The "Bouncer" (Hard Size Limit)
This is the simplest and most effective fix. Dependencies are heavy; source code is light.

If we set a strict upload limit of 15MB in Flask, any zip file containing node_modules or venv will likely get rejected immediately before it even finishes uploading.

In config.py or your main app setup:

Python

# Reject any upload larger than 15MB
app.config['MAX_CONTENT_LENGTH'] = 15 * 1024 * 1024 
User Experience: If they try to upload a bloated zip, the upload fails instantly, and you show a flash message: "File too large (Max 15MB). Please delete 'node_modules' or 'venv' and try again."

Layer 2: The "Surgeon" (Smart Unzipping)
Even if a small node_modules folder sneaks past the size limit (e.g., a small project), we do not have to extract it.

We can write our Python unzip function to "peek" inside the zip file first. It will look at the file names and skip anything that looks like a dependency folder.

Here is the "Smart Unzip" code for your InputManager:

Python

import zipfile
import os

def smart_unzip(zip_path, extract_to):
    # Folders we absolutely refuse to extract
    IGNORE_FOLDERS = {'node_modules', 'venv', '.env', '.git', '__pycache__', 'dist', 'build'}
    
    with zipfile.ZipFile(zip_path, 'r') as zip_ref:
        # Get list of all files inside without extracting yet
        all_files = zip_ref.namelist()
        
        for file in all_files:
            # Check if file is inside a forbidden folder
            # e.g. "my_app/node_modules/library/index.js" -> parts=['my_app', 'node_modules', ...]
            path_parts = file.split('/')
            
            # If any part of the path is in our ignore list, SKIP IT.
            if any(part in IGNORE_FOLDERS for part in path_parts):
                continue 
            
            # If it's safe, extract only that file
            zip_ref.extract(file, extract_to)
Result: Even if the user uploads a zip full of junk, your server only writes the actual source code to the disk.

Layer 3: The "Git" Advantage
This is why the Git URL method I mentioned earlier is superior.

When users push code to GitHub/GitLab, they (should) use a .gitignore file. This means node_modules and venv strictly do not exist in the repository.

If your tool clones the repo, you automatically get clean code without dependencies.

Recommendation: In your UI, make the "Git URL" option the default/primary choice, and "Upload Zip" the secondary choice.
