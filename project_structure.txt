1. The Grand Architecture
We will move away from "one file per scanner" and move toward a Plugin Architecture. Your Flask app will act as the "General," and the tools are the "Soldiers."

The Pipeline Flow:

Input: User creates a "Project" (URL + Source Code + Cloud Creds).

Orchestration: The System spawns independent threads for each tool.

Normalization: A specialized "Parser" converts every tool's weird JSON output into a single standard format.

Compliance Engine: Maps the Normalized Findings to PCI/ISO/GDPR.

Reporting: Generates the Master Audit PDF.

2. System Prerequisites (The Installation List)
Before writing code, your server needs these tools installed. You cannot run subprocess if the binary isn't there.

The "apt-get" / Install List:

Semgrep: pip install semgrep

Checkov: pip install checkov

Gitleaks: Download binary (Go-based) or brew install gitleaks (Linux/Mac).

Nmap: sudo apt-get install nmap

Prowler: pip install prowler (Requires AWS CLI configured).

ZAP: Already installed.

3. Database Design (The Backbone)
We need a robust schema to handle this. We shouldn't store 6 different types of results. We store Raw Reports and Normalized Findings.

New Models (extensions.py):

AuditProject: Represents the target (e.g., "E-commerce V1").

id, name, target_url, source_code_path, cloud_provider.

AuditRun: A specific execution time.

id, project_id, timestamp, status (Running/Completed).

ScanResult: The raw output file from a specific tool.

id, run_id, tool_name (e.g., 'Semgrep'), raw_json_path.

Finding: The normalized vulnerability.

id, run_id, tool_source, severity (Critical/High...), cwe_id, description, file_location.

ComplianceReport: The final score.

id, run_id, standard (PCI/GDPR), score, compliance_data_json.

5. The "Normalizer" (Crucial Step)
Every tool speaks a different language. We need a translator.

Semgrep outputs: {"results": [{"check_id": "...", "path": "..."}]}

Gitleaks outputs: [{"Description": "...", "File": "..."}]

Nmap outputs: XML (usually).

We will create Services/normalizer.py:

Python

def normalize_finding(tool_name, raw_data):
    # Returns a standard object:
    return {
        "tool": tool_name,
        "name": raw_data['title'],
        "severity": map_severity(raw_data['severity']), # Map all to HIGH/MED/LOW
        "cwe": raw_data.get('cwe', 'Unknown'),
        "description": raw_data['message']
    }
6. Execution Plan (Step-by-Step)
We cannot code this all at once. It will break. Here is the sprint plan:

Phase 1: The Foundation (Day 1-2)

Create the Database Models.

Create the New Route (/audit) and UI Page (audit_dashboard.html).

Build the File Uploader (User must be able to upload a .zip of source code).

Phase 2: The Static Bundle (Day 3-4)

Implement Semgrep, Checkov, and Gitleaks.

Why? They all scan local files. They are easier to test than ZAP/Nmap.

Write the normalizer.py for these three.

Phase 3: The Network Bundle (Day 5)

Integrate Nmap.

Refine the ZAP integration to feed into the central database instead of being standalone.

Phase 4: The Compliance Brain (Day 6)

Update compliance_engine.py to map findings from all 5 tools to PCI-DSS/ISO.

"If Nmap finds Port 23 (Telnet) -> Fail PCI Req 1."

"If Gitleaks finds AWS Key -> Fail ISO A.9."

Phase 5: The Cloud (Day 7 - Hardest)

Integrate Prowler.

Note: This requires handling AWS Keys securely. For MVP, we might ask the user to upload a Prowler JSON report manually instead of running it, to avoid liability of holding their root keys.
